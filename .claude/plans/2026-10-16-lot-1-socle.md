# Lot 1 du modèle de projet — le socle : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** créer `EdouardZemb/modele-projet`, un modèle Copier dont la cible `aucune` livre la méthode et les garde-fous du socle, puis l'éprouver par une naissance (`Nouveau-Projet.ps1`) et par l'alignement d'`ancrage`.

**Architecture :** le dépôt `modele-projet` contient `copier.yml` et un dossier `template/` rendu dans chaque projet. Les garde-fous sont des scripts Python sans dépendance (`template/scripts/modele/`), appelés par des hooks git en `sh`, par un hook Claude Code et par un workflow GitHub réutilisable. Deux scripts PowerShell hors dépôt, dans `Documents\30-ressources\35-dev\`, créent les projets et surveillent la dérive.

**Tech Stack :** Copier 9.19.1, Python 3.12 (bibliothèque standard seule pour les scripts du modèle), pytest 9.1.1, ruff 0.17.1, PyYAML 6.0.3 (tests seulement), `sh` de Git for Windows, Windows PowerShell 5.1, GitHub Actions, `gh` 2.93.

**Spec :** `Documents\00-boite-de-reception\2026-10-16-modele-projet-design.md`, hors dépôt parce qu'elle nomme le serveur. Ce plan applique ses §3, 4, 5, 8, 10, 11 (lot 1) et 12. **Ce plan est écrit pour être versionné dans `modele-projet`, qui est public** : il ne nomme ni le serveur, ni son utilisateur, ni aucune adresse. Il doit le rester.

**Durée de vie :** le plan entre dans `.claude/plans/` au premier commit. La PR de clôture (tâche 14) le **supprime**, et ce qui doit survivre passe dans `CLAUDE.md`, `docs/cadrage.md` ou un ADR.

## Global Constraints

- Les scripts de `template/scripts/modele/` n'utilisent que la bibliothèque standard de Python, en 3.10 ou plus. Un projet n'installe rien pour avoir ses garde-fous.
- Tous les fichiers texte sont en LF. `.gitattributes` vaut `* text=auto eol=lf`, dans `modele-projet` comme dans `template/`. Le poste a `core.autocrlf=true` au niveau système : sans cette ligne, Copier rendrait des hooks en CRLF, que `sh` n'exécute pas.
- Seuls les fichiers qui ont besoin d'une variable portent le suffixe `.jinja`. Un fichier qui contient `${{` n'est jamais `.jinja`, sauf si chaque expression GitHub y est enveloppée dans `{% raw %}…{% endraw %}`.
- `template/docs/modele/methode.md` ne contient aucune syntaxe Jinja : `modele-projet` l'importe tel quel dans son propre `CLAUDE.md`.
- Aucun fichier versionné de `modele-projet` ne nomme le serveur, son utilisateur, une adresse IP ou un nom Tailscale. La porte de confidentialité, avec la liste privée, doit passer sur `git ls-files`.
- La porte de confidentialité n'affiche jamais la valeur trouvée, ni le texte d'un motif privé : seulement l'emplacement et le nom du motif. Les journaux d'Actions d'un dépôt public sont publics.
- Tout est en français : documents, messages des scripts, commits. Les commits suivent Conventional Commits, avec un en-tête de 100 caractères au plus, et finissent par les lignes d'attribution de la session.
- Les actions sont épinglées par SHA :
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1` ;
  - `actions/setup-python@5fda3b95a4ea91299a34e894583c3862153e4b97 # v7.0.0` ;
  - `gitleaks/gitleaks-action@e0c47f4f8be36e29cdc102c57e68cb5cbf0e8d1e # v3.0.0`.
- Les `.ps1` sont enregistrés en UTF-8 **avec** BOM. Les fichiers qu'ils écrivent, en particulier `INDEX-PROJETS.md`, gardent leur encodage d'origine : UTF-8 **sans** BOM, en LF.
- Edouard seul crée un dépôt GitHub, pose un secret ou une règle de protection, pose une étiquette, archive un dépôt (étapes 👤). Une session peut pousser une branche et ouvrir ou fusionner une PR, une fois tous les contrôles verts.
- Les worktrees vivent dans `<dépôt>.worktrees\<sujet>`. Avant de lire un fichier texte inconnu : `python Documents\00-boite-de-reception\_journal-rangement\_scripts\detecter-secrets.py <fichier>`.
- Ajouter `C:\src` à la session (`/add-dir C:\src`) avant toute tâche côté code.

## Review Focus

1. **Une porte qui fuit dans les journaux publics.** La valeur trouvée ou un motif privé imprimé par `confidentialite.py` serait publié dans le journal d'Actions. On attend : l'emplacement et le nom du motif, jamais le texte. Test : `test_sortie_ne_divulgue_rien`, tâche 4.
2. **Des hooks qui ne s'exécutent pas, sans un mot.** Trois causes : un hook en CRLF, un hook sans bit exécutable sous Linux (un `git add` sous Windows enregistre `100644`), et le `python3` du Microsoft Store, qui n'est pas Python. On attend : les hooks tournent sur le poste, en CI et dans une session à distance. Tests : `test_hooks_lf_et_executables` et `test_lancer_trouve_un_python`, tâche 6. Le `git update-index --chmod=+x` est fait aux tâches 11 et 13.
3. **Un agent qui contourne.** `--no-verify`, `-c core.hooksPath=…`, `cd x && git push origin main`, l'outil PowerShell au lieu de Bash, `gh pr merge --admin`, la fusion par `gh api`. On attend un refus pour chacun. Test : la table `REFUS` de `test_garde_claude.py`, tâche 7.
4. **Un index corrompu.** `Nouveau-Projet.ps1` y écrirait un BOM ou des CRLF, ou ajouterait sa ligne dans le mauvais tableau. Or l'index est lu par le contrôle de dérive et par chaque session. On attend : un seul changement, la ligne ajoutée après la dernière ligne du premier tableau. Test : la comparaison octet par octet de `Tester-Nouveau-Projet.ps1`, tâche 11.
5. **Des contrôles requis que personne ne produit.** Si un nom de contexte du *ruleset* ne correspond pas au nom réel du contrôle, aucune PR ne peut plus être fusionnée. On attend que les noms coïncident. Tests : `test_ruleset_coherent` (tâche 8) et `test_ruleset_du_depot_modele` (tâche 10). Vérification réelle sur `modele-essai` (tâche 11), puisque la règle de nommage `<job appelant> / <job appelé>` d'un workflow réutilisable n'est pas encore vérifiée.

### Task 4 : la porte de confidentialité

**Files :**
- Create : `template/scripts/modele/confidentialite.py`
- Test : `tests/test_confidentialite.py`

**Interfaces :**
- Produces (dans `confidentialite.py`) :
  - `@dataclass(frozen=True) class Motif: nom: str; expression: re.Pattern[str]`
  - `MOTIFS_GENERIQUES: tuple[Motif, ...]`, avec les noms et expressions fixés au Step 3.
  - `charger_motifs_prives(texte: str) -> tuple[Motif, ...]`. Une ligne vide ou en `#` est ignorée. `re:` introduit une expression régulière, toute autre ligne un littéral (`re.escape`), dans les deux cas avec `re.IGNORECASE`.
